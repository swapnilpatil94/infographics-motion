# Skeleton-character milestone — final report

The Short is the acceptance test: `output/shorts/skeleton_factory_proof/final.mp4` (38.1 s, 1080×1920, 30 fps, Hindi narration, 13 shots). Everything below is measured, not claimed (`qc_report.json`: 30/30 checks pass).

1. **Rig system selected** — none of the four. A **stock-Blender-5.2.2 armature + IK rig generated by our own code** (`engine/blender/skeleton_scene.py` from `engine/skeleton/rig_def.py`), borrowing concepts from COA Tools 2 (sprite meshes skinned to bones, IK on limbs), Puppet Mode (eye/eyebrow/jaw bones), Tiny 2D Rig Tools (human hierarchy), skeleton-rig (skeleton/art/motion as separate data).
2. **Why** — all four were actually run in Blender 5.2.2 (`docs/RIG_RESEARCH_V2.md`, probes in `docs/rig_probe/`): COA Tools 2 works but is **GPL-3** (cannot be vendored into the core); Tiny 2D Rig Tools builds a 21-bone armature but has **no licence**, its IK init needs UI state; Puppet Mode builds 55 bones but its Grease Pencil layers came out **empty on 5.2** and it has no licence; skeleton-rig is a browser app (no licence). Nothing was installed into Blender; nothing is vendored.
3. **Open-source assets downloaded / used** — Open Peeps (already on disk, 1 074 SVG atoms; only head/hair atoms + nose are used). Humaaans evaluated via a mirror clone (not used). All limbs/torso/hands/feet/phone are own-work generated art.
4. **Exact URLs** — https://www.openpeeps.com/ · https://www.humaaans.com/ · https://github.com/jktzes/humaaans (mirror) · https://github.com/Aodaruma/coa_tools2 · https://github.com/NickTiny/Tiny-2D-Rig-Tools · https://github.com/8bitbyadog/puppet-mode · https://github.com/frycz/skeleton-rig
5. **Exact licences** — Open Peeps **CC0**; Humaaans **CC0** (site) / mirror `jktzes/humaaans` **MIT** / mirror `Calinou/humaaans` CC-BY-4.0; COA Tools 2 **GPL-3.0**; Tiny 2D Rig Tools, Puppet Mode, skeleton-rig **no licence**. Decisions produced by the live tool `tools/assets/verify_license.py` (see `docs/ASSET_ACQUISITION_V2.md`).
6. **Where files are stored** — `assets/character/raw/open_peeps/` (atoms), `assets/character/generated/` (head shells), `assets/character/skeleton/generated/<hash>/` (per-character part PNGs + `parts.json`), `assets/environment/generated/bedroom_wide_*`, research clones in `/tmp/rigresearch/` (outside the repo).
7. **How the character is modularised** — 20 independent parts: upper arm, forearm, hand ×2 sides; thigh, shin, foot ×2; torso, pelvis, neck, skull, **hair (separate layer)**, nose, held phone, gripping fingers. Face = flat-colour meshes (eye white/ring/pupil, brows, mouth line + cavity), not images.
8. **How the skeleton works** — 26 bones: ROOT › PELVIS › SPINE › CHEST › NECK › HEAD › (HAIR, EYE_L/R, BROW_L/R, MOUTH); CHEST › SHOULDER › ARM › FOREARM › HAND; PELVIS › THIGH › SHIN › FOOT. Each part mesh is skinned 100 % to one bone. Proportions come from the DNA; topology is identical for every character (asserted in QC + tests).
9. **How IK works** — 4 Blender `IK` constraints (2-bone, `use_tail`, X/Y locked, Z limits). Targets are empties animated in world space. The solver only finds the natural bend if it starts near it, so each frame's FK pose is seeded with the analytic 2-bone solution; Blender's IK then solves to the target. Measured error vs. targets: **0.0 px** on every probed frame (40 probed frames of the Short + all tests).
10. **Motion primitives** — 36 semantic actions: idle, blink, look_left/right/down/up/ahead, look_at_phone, head_turn, head_tilt, shrug, walk, sit, stand, reach(_for_phone), grab, hold_phone, read_phone, point, gesture, talk, listen, fear, surprise, confusion, realization, face, wake, slump, buzz, hangup, hand_down. Command form `{"action","emotion","intensity",…}`; 11 emotion styles × intensity.
11. **Character variation** — DNA → skin (8 tones), Open Peeps hair atoms (gender-strict), facial hair, glasses, eyes/brows/mouth style, outfit (colour, pattern, collar, sleeve length, long top), trousers, shoes, hair colour, build (slim…heavy), age proportions, height scale. Same bones, same actions.
12. **Character variants generated** — **24** in `character_factory_contact_sheet.png` (24 unique DNA, 15 archetypes) + 32 in the crowd + 4 named (A young male, B young female, C middle-aged male, D middle-aged female); A and D act in the Short.
13. **Characters in the crowd** — **32**, all unique DNA, 18 hair styles, 13 outfits, 30 distinct heights, 22 facing left / 10 right, 6 action kinds (walk, idle, talk, phone, point, wave), 4 depth rows.
14. **Did Blender generate the rig?** — **Yes.** `skeleton_scene.py` creates every armature, IK constraint, skinned mesh, vertex group, shape key and material headlessly from a JSON job. Nobody opens Blender. The saved scene is `work/skeleton_scene.blend`.
15. **Did Blender animate the rig?** — **Yes.** Every channel is inserted as real keyframes (bone rotation/location/scale, IK empties, shape-key values, visibility, camera) and Blender evaluates the animation + IK solver per frame (25 action datablocks, 975 frames rendered). The 2D compositor then lays the RGBA actor frames into the 2.5D set — see limitations.
16. **Exact render command** — `python3 studio.py --skeleton-short` (Chatterbox voice; add `--tts vibevoice` for the VibeVoice batch path; `--tempo 1.16`).
17. **Exact `--from-plan` command** — `python3 studio.py --from-plan output/shorts/skeleton_factory_proof/plan.json` (no LLM, no TTS, no analysis). **Determinism proven:** a second run into a fresh folder gave 975/975 pixel-identical Blender frames, byte-identical plan, and identical SHA-256 for the decoded video and decoded audio.
18. **QC results** — 30/30 pass (`qc_report.json`): 1080×1920, 30 fps, 38.13 s, −16.2 LUFS, no unintended black frames, no frozen frames, 26 bones and 4 IK constraints per character, IK error 0.0 px, same rig for both characters, 75 sampled full-body frames (head-to-feet visible), 416 sitting + 716 standing frames (pelvis travel 192 px), real walk (3 steps, 302 px root travel, 47 foot-swing frames, planted stance feet), reach (196 px hand travel = 61 % of arm length) + phone pick-up event, 12 blinks, gaze range 2.2 × 1.2, head rotation 28°, 21 distinct expressions, 12 environment layers with 10 parallax factors, measured dolly-through parallax (near vs far layer shift 2 274 px), 7 shot sizes / 5 camera moves, luma span across shots ≥ 0.08, 6 Grease Pencil effects + a procedural money shot, every cut lands 0.12 s before its beat, captions inside the safe zone.
19. **Known limitations** — see below.

## Narration pacing (the second request)
Natural Chatterbox Hindi was 2.34 words/s. Dead-air trimming (in-beat gaps ≤ 0.14 s, 0.10 s between beats) + pitch-preserving 1.16× tempo → **2.97 words/s** (37 s vs 46.5 s), hook-first short sentences, cuts led by 0.12 s. **VibeVoice Hindi 7B was tried** (it needed two environment fixes to run at all — see `docs/NARRATION_TTS_TEST.md`): intelligibility (Whisper large-v3 vs. script) was 0.25–0.94 per batch vs. Chatterbox 0.89–0.95, with ~11 s of dead air per 41 s, degradation in long-form and ~10× slower generation, so **Chatterbox is used**; VibeVoice stays selectable with `--tts vibevoice`. I could not listen to either voice, so subjective quality is unjudged.

## Limitations (honest)
* **Side-on characters only** (flat 3/4 profile: Open Peeps head, profile body). No front/back views, no mid-shot turn-around; two characters can face each other.
* **Blender renders only the characters** (flat emission + AA). The room, lighting, focus, Grease Pencil FX, captions and colour are the existing 2D compositor; characters get its light-map, not Blender lighting. So this proves a Blender-generated, Blender-animated, Blender-IK-solved rig, **not** a fully Blender-rendered film.
* Body art is simple own-work (capsule limbs, mitten hands); no finger articulation beyond the phone-grip overlay; long garments are a longer torso block, not cloth.
* Sit/stand assume one seat height per scene; walking is straight-line on a flat floor; A/D overlap when standing very close.
* The Short is 38 s in one room with 2 acting characters; the 24-character sheet and 32-character crowd are separate test videos.
* Facial acting is minimal by design (dot eyes, thin brows); micro-expressions are limited to brow tilt/raise/asymmetry, eye scale (blink/droop/wide), gaze, and mouth open/smile/frown.
* VibeVoice quality was judged only by ASR similarity; Chatterbox is not a native narrator voice.
